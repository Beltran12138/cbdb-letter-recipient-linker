# run4 结果：积压批次切分（2026-10-04；预注册见 PREREG_addendum_run4.md；本批次只跑一次）

场景：只用 CBDB 2022-07-27 版 + 当时 4,870 封书信金标训练，预测 2022-07 → 2023-03 窗口新增的 9,738 封（CSA 明代书信批次）。

| | n | 全量 Top-1 | 置信度 ≥ T97(0.945)：覆盖 / 实际精度 |
|---|---|---|---|
| **全部（预注册主结果）** | 9,738 | **87.1%** | **51.1% / 97.7%** |
| 固定阈值 0.9（预注册辅助） | 9,738 | — | 62.8% / 97.6% |
| 事后分层：CSV 当时已填 | 2,459 | 88.9% | 50.8% / 98.0% |
| 事后分层：不在 CSV 中 | 6,616 | 92.6% | 55.6% / 97.9% |
| 事后分层：**CSV 当时为空（后来识别）** | 704 | **24.1%** | **7.7% / 77.8%** |

- 候选召回 91.1%；训练集 OOF 校准良好（0.9–1.0 档平均概率 0.96 → 实际 0.96）
- 停止线（主结果）未触发：高置信错误率 2.3%
- 别名泄漏检查：命中 2022-07 版别名的 8,757 封中，别名来源 = 本信文集仅 2 封
- 已知污染：候选规则设计参考过约 45 个 2026 版训练集样例，部分属于本批次

## 解读
1. 系统擅长的，正是人工也容易识别的那一大块（约九成）；对人工也难的残余（CSV 当时为空的那部分），Top-1 只有 24%，且大多会主动弃答（覆盖 7.7%）——但在这部分作答时精度只有 78%（n≈54，置信区间宽）
2. 与 run2 困难划分（43.6%）、run3（全量 19%，被无标题书信稀释）一致：**难度来自书信本身，不来自时间**
3. 价值定位（推断，待向 CBDB 核实）：适合给**新录入文集**做第一遍自动识别（2022 年时能以约 98% 精度自动识别约一半）；对已经被人工挑剩下的难题帮助很小

## 更正（2026-10-07，事后稳健性检查，不是重新调参）

从公开仓库的干净副本重跑 run4，覆盖率复现不出 51.1%。查明两个原因：

1. **结果随 `PYTHONHASHSEED` 变化**：`features_v2.py` 里 R2 规则遍历一个字符串 set，顺序随哈希种子变，导致候选顺序变，HGB 的训练结果也跟着变。已改为按姓在标题中的出现顺序遍历。修复后用两个不同的哈希种子重跑，输出逐字相同（T = 0.945，覆盖 50.7%，精度 97.6%，Top-1 87.1%）。
2. **预注册的阈值规则不稳定**：「训练集 OOF 精度 ≥ 97% 的最小阈值」这条规则落在 OOF 精度曲线平坦的那一段。`run4_stability.py` 重复 10 次，每次只改候选顺序、GroupKFold 分组和模型种子，结果（`run4_stability.log`）：

| | 中位数 [最小, 最大] |
|---|---|
| 规则选出的 T | 0.96 [0.94, 1.0] |
| 覆盖（≥ T） | 45.7% [0%, 54.4%] |
| 精度（≥ T，不计零作答那次） | 98.0% [97.8%, 98.2%] |
| Top-1 | 87.1% [86.9%, 87.4%] |
| 覆盖（≥ 0.9，预注册辅助阈值） | 62.1% [58.0%, 65.9%] |
| 精度（≥ 0.9） | 97.6% [97.4%, 97.9%] |

其中一次（seed 2）OOF 精度在任何阈值上都没到 97%，规则返回 T = 1.0，结果是全部弃答。

**今后口径**：报固定阈值 0.9 的结果。修复后的确定性运行：全部 9,738 封，覆盖 62.2%，精度 97.4%；「CSV 当时为空」的 704 封，Top-1 24.0%，覆盖 11.4%，精度 83.8%（67/80）。上表中「51.1% / 97.7%」作废。停止线仍未触发（≥ 0.9 时高置信错误率 2.1–2.6%）。
